# マイグレーション (Migration)

## 概要
マイグレーションとは、**「設計図（schema.prisma）の内容を、実際のデータベースに反映させる作業」**のことです。

家づくりに例えてみましょう。
`schema.prisma` は「家の設計図」です。データベースは「実際に建っている家」です。
設計図に「新しい部屋を追加する」と書き込んだだけでは、実際の家は変わりません。大工さんが工事をしてから、実際の家に部屋が追加されます。

この「工事」にあたるのがマイグレーションです。
Prismaにおけるマイグレーション機能（Prisma Migrate）を使うと、`schema.prisma` の変更内容を読み取り、自動的にデータベースの構造（テーブルやカラム）を作り変えてくれます。

## 特徴

### 1. データベースの変更履歴が残る
マイグレーションを行うと、「いつ」「どのような変更をしたか」という履歴がファイルとして保存されます。
これにより、過去の状態に戻したり、チームメンバーとデータベースの構造を共有したりすることが簡単になります。

### 2. 安全にデータベースを更新できる
手作業でデータベースをいじると、誤って大切なデータを消してしまうリスクがあります。
Prismaのマイグレーション機能は、データが消える可能性がある変更（例：列の削除など）を行う際に、事前に警告を出してくれます。

### 3. SQLを書かずに済む
通常、データベースを操作するには「SQL」という専門言語を使う必要があります。
しかし、Prismaを使えば `schema.prisma` を書き換えてコマンドを実行するだけで、裏側で必要なSQLを自動生成して実行してくれます。

## 使い方

マイグレーションを実行するには、ターミナル（コマンドラインツール）で以下のコマンドを使用します。

```bash
npx prisma migrate dev --name <変更内容を表す名前>
```

このコマンドを実行すると、以下のことが行われます。

1.  `schema.prisma` の内容と現在のデータベースの状態を比較します。
2.  差分（変更点）を反映するためのマイグレーションファイル（SQLファイル）を作成します。
3.  そのファイルをデータベースに対して実行し、構造を更新します。
4.  最後に、プログラムからデータベースを操作するための便利なツール（Prisma Client）を再生成します。

たとえば、`schema.prisma` に新しいモデルを追加した後に `npx prisma migrate dev --name init` と実行するだけで、データベースに新しいテーブルが作成されます。
