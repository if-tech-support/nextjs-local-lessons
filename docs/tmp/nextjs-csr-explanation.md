# Next.jsにおけるCSR（クライアントサイドレンダリング）について

## 概要

CSR（Client-Side Rendering）とは、Webページの表示内容を**ユーザーのブラウザ（クライアント）側で生成する仕組み**のことです。

例えるなら、レストランで料理を注文したときに、完成した料理が運ばれてくるのではなく、「カットされた食材」と「調理器具」がテーブルに運ばれてきて、**お客さん自身がその場で調理して食べる**スタイルに似ています。

Next.jsのApp Routerでは、基本的にはサーバー側でページを作ってからブラウザに送ります（サーバーコンポーネント）。しかし、ユーザーの操作に応じて画面を変化させたい場合などは、このCSRの仕組みを利用して、ブラウザ側で処理を行う必要があります。

## 特徴

CSRには以下のような特徴があります。

*   **ユーザーの操作に即座に反応できる**: ボタンをクリックしたときに数値をカウントアップしたり、入力フォームの内容に応じて表示を変えたりといった、動きのある表現が得意です。
*   **ページ遷移がスムーズ**: ページ全体を再読み込みするのではなく、必要な部分だけを書き換えることができるため、アプリのようなサクサクとした操作感を実現できます。
*   **ブラウザの負荷**: 画面を作る作業をブラウザが行うため、複雑な処理をさせすぎると、スペックの低いスマートフォンなどでは動作が重くなる可能性があります。

Next.jsでは、`page.js` や `layout.js` はデフォルトでサーバー側で処理されますが、CSRを行いたい部品（コンポーネント）だけを明示的に指定して使うことができます。

## 使い方

Next.js（App Router）でCSRを行うには、ファイルの先頭に `'use client'` という宣言を記述します。これを記述したファイルは「クライアントコンポーネント」となり、ブラウザ側でJavaScriptが実行されるようになります。

主に以下のような場面で使用します。

1.  `onClick` や `onChange` などのイベントリスナーを使いたい場合
2.  `useState` や `useEffect` などのReactフックを使いたい場合
3.  ブラウザ専用のAPI（`window` や `document` など）を使いたい場合

### コード例

以下は、ボタンをクリックすると数字が増えるカウンターの例です。ユーザーの操作（クリック）によって画面が変わるため、CSR（クライアントコンポーネント）として実装します。

```tsx
'use client'; // この1行を書くことでCSR（クライアントコンポーネント）になります

import { useState } from 'react';

export default function Counter() {
  // 状態管理（useState）はクライアント側でのみ動作します
  const [count, setCount] = useState(0);

  return (
    <div className="p-4 border rounded">
      <p className="mb-2">現在のカウント: {count}</p>
      <button
        className="bg-blue-500 text-white px-4 py-2 rounded"
        onClick={() => setCount(count + 1)} // クリックイベントもクライアント側でのみ動作します
      >
        増やす
      </button>
    </div>
  );
}
```

このように、`'use client'` を宣言することで、そのコンポーネント内でインタラクティブな機能（動きのある機能）を実装できるようになります。
