# prisma.config.ts について

## 概要
`prisma.config.ts` は、Prismaを動かすための「設定」を記述するファイルです。

これまでは `schema.prisma` というファイルだけですべての設定を行っていましたが、新しいバージョンのPrismaからは、この `prisma.config.ts` を使って設定を書くことができるようになりました。

例えるなら、これまでは「紙の地図」を見て目的地を探していたのが、「カーナビ」を使えるようになったようなものです。目的地に行くという目的は同じですが、より便利で、間違いが起きにくい方法で設定を行えるようになりました。

## 特徴

### 1. 書き間違いを自動で防げる
このファイルはTypeScript（タイプスクリプト）というプログラミング言語で書かれています。そのため、もし設定の書き方を間違えてしまっても、エディター（プログラムを書くソフト）が「ここが間違っていますよ」と赤線などで教えてくれます。これにより、設定ミスによるトラブルを未然に防ぐことができます。

### 2. 柔軟な設定ができる
プログラミング言語を使って設定を書けるため、単に文字を並べるだけでなく、「もしAならBにする」といった条件を付けたり、計算した結果を設定に使ったりと柔軟な書き方ができます。

### 3. 他のツールと統一感がある
Next.jsなど、最近のWeb開発で使われる多くのツールも、同じような形式（`config.ts` という名前のファイル）で設定を行います。そのため、他のツールの使い方を知っていれば、同じような感覚でPrismaの設定も扱うことができます。

## 使い方
基本的には、Prismaをプロジェクトに導入する際に自動的に作成されます。
ファイルの中には、「データベースの設計図（スキーマファイル）がどこにあるか」や「データベースへの接続情報」などが記載されています。

通常は自動生成された内容のままで問題ありませんが、ファイルの場所を変更したい場合などにこのファイルを編集します。

以下は、`prisma.config.ts` の中身の例です。

```ts
// Prismaの設定を行うための機能を読み込みます
import { defineConfig } from "prisma/config";

export default defineConfig({
  // データベースの設計図（スキーマファイル）がどこにあるかを指定します
  schema: "prisma/schema.prisma",
  
  // データベースの変更履歴（マイグレーション）を保存する場所を指定します
  migrations: {
    path: "prisma/migrations",
  },
  
  // データベースへの接続情報を設定します
  datasource: {
    // 環境変数（秘密の値を保存する場所）からデータベースのURLを読み込みます
    url: process.env["DATABASE_URL"],
  },
});
```
